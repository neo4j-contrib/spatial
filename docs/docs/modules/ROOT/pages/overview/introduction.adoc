= Introduction

http://github.com/neo4j-contrib/spatial[Neo4j Spatial] is a library of utilities for Neo4j that facilitate the enabling of spatial operations on data.
In particular, you can add spatial indexes to already located data, and perform spatial operations on the data like searching for data within specified regions or within a specified distance of a point of interest.
In addition, classes are provided to expose the data to GeoTools and thereby to GeoTools-enabled applications like GeoServer and uDig.

image::one-street.png[scaledwidth="75%"]

The key features include:

* Utilities for importing from ESRI Shapefile as well as Open Street Map files
* Support for all the common geometry types: Point, LineString, Polygon, etc.
* An RTree index for fast searches on geometries
* Support for topology operations during the search (contains, within, intersects, covers, disjoint, etc.)
* The possibility to enable spatial operations on any graph of data, regardless of the way the spatial data is stored, as long as an adapter is provided to map from the graph to the geometries.

== Get Started

The easiest way to get started with neo4j-spatial is to grab the `neo4j-spatial-server-plugin-x.x.x-with-dependencies.jar` from https://github.com/neo4j-contrib/spatial/releases[the latest release], copy it to your `$NEO4J_HOME/plugins` and restart your Neo4j server.

NOTE: OpenStreetMap label:OSM[] features are shipped in a separate, optional plugin JAR (`neo4j-spatial-osm-server-plugin-x.x.x-with-dependencies.jar`). To enable OSM-specific imports and endpoints, add that JAR along with the main server-plugin to `$NEO4J_HOME/plugins`.

=== Docker

Use the official https://hub.docker.com/_/neo4j[`neo4j`] image with the same version as the plugin, and mount the directory holding the plugin JAR(s) into `/plugins`:

[source,shell,subs="attributes+"]
----
docker run -p 7474:7474 -p 7687:7687 \
  -v "$PWD/plugins:/plugins" \
  -e NEO4J_dbms_security_procedures_unrestricted='spatial.*' \
  neo4j:{docs-version}
----

=== Usage

Once installed, you can use all the xref:api/index.adoc[spatial procedures and functions] in your Cypher queries to add Nodes to the spatial index and perform a number of spatial point, distance and intersection queries.

.Simple Example
[source,cypher]
----
CALL spatial.addPointLayer('geom');
CALL spatial.layers();

CREATE (n:Node {latitude:60.1,longitude:15.2})
WITH n
CALL spatial.addNode('geom',n) YIELD node
RETURN node;

CALL spatial.bbox('geom',{lon:15.0,lat:60.0}, {lon:15.3, lat:61.0});
----

[[spatial-concurrency]]
== Concurrency

Each layer supports only one writer at a time.
The RTree index has no locking of its own, so concurrent writes to the same layer (`spatial.addNode(s)`, `spatial.addWKT(s)`, `spatial.removeNode(s)`, `spatial.updateWKT`, imports) can fail with a `DeadlockDetectedException` and need to be retried.
Serialize writes per layer; reads, and writes to different layers, can run concurrently.

[[spatial-changing-indexed-nodes]]
== Changing indexed nodes

Layers only change through the `spatial.*` procedures; direct graph writes don't update them (https://github.com/neo4j-contrib/spatial/issues/496[#496]):

* Call `spatial.removeNode` before deleting an indexed node. Otherwise the layer's bounding boxes and feature count go stale.
* After changing a node's geometry properties, call `spatial.addNode` again for every layer that holds it.
